# SDUD SGLT2 Inhibitor Extraction Workflow Report
## Project aim
The aim of this workflow was to extract U.S. Medicaid State Drug Utilization Data (SDUD) records for sodium-glucose cotransporter-2 inhibitors (SGLT2 inhibitors) from 2015 to 2025, using a reproducible NDC-based approach. The extracted dataset is intended for downstream analysis of state-level SGLT2 inhibitor uptake, particularly in relation to rurality, socioeconomic deprivation, heart failure burden, cardiologist density, Medicaid expansion, and other state-level covariates.
The primary planned outcome is state-quarter SGLT2 inhibitor prescribing volume, measured using the SDUD variable `Number of Prescriptions`. This will later be converted into prescribing rates using Medicaid enrolment denominators, or modelled as a count outcome using Medicaid enrolment as an offset.

Key SDUD variables

Utilization Type

This variable identifies the type of Medicaid utilization record.

FFSU = Fee-for-Service Utilization
MCOU = Managed Care Organization Utilization

From 2010 onward, SDUD can contain both FFSU and MCOU records. For this analysis, both were retained and summed together in the main state-quarter outcome. This is important because excluding managed care records would undercount prescribing in states where a large proportion of Medicaid beneficiaries are enrolled in managed care.

Number of Prescriptions

This is the primary prescribing volume variable. It represents the number of Medicaid-reimbursed prescriptions for a specific NDC in a given state, year, and quarter.

This was selected as the main utilisation outcome because it is a direct measure of medication uptake. Reimbursement variables were retained for secondary cost analyses but were not selected as the primary uptake outcome because reimbursement values are affected by drug prices, dispensing fees, payment arrangements, and do not reflect net costs after rebates.

Units Reimbursed

This represents the number of units reimbursed, based on the drug’s unit type. It was retained as a secondary utilisation measure.

Medicaid Amount Reimbursed

This represents the amount reimbursed by Medicaid to pharmacies for the drug. This is a gross reimbursement measure and is not reduced by manufacturer rebates.

Total Amount Reimbursed

This includes Medicaid and non-Medicaid amounts reimbursed to pharmacies. This was retained but should be interpreted cautiously.

NDC conversion approach

The FDA package file gives NDC package codes in hyphenated formats such as:

82381-2174-1
51407-918-30
50458-140-01
50090-5034-1

The SDUD dataset uses an 11-digit NDC code. Therefore, FDA package NDCs were converted to the standard 11-digit 5-4-2 format:

5 digits = labeler code
4 digits = product code
2 digits = package code

The conversion logic was:

4-4-2 format → add leading zero to labeler segment
5-3-2 format → add leading zero to product segment
5-4-1 format → add leading zero to package segment

Examples:

82381-2174-1  → 82381217401
51407-918-30  → 51407091830
50458-140-01  → 50458014001
50090-5034-1  → 50090503401

The output from this process was an SGLT2 inhibitor NDC lookup table:

This table included the following columns:

The lookup table had repeated proprietary names because the same medication can have multiple package-level NDCs due to different strengths, pack sizes, package descriptions, labelers, and formulations. This is expected and appropriate because SDUD records are also reported at the NDC level.

The important uniqueness check was at the ndc_11 level. The lookup table was made distinct by ndc_11 before joining to SDUD.

Combination product handling

Combination products were identified using the generic and brand names. Examples include:

empagliflozin + metformin

dapagliflozin + metformin
dapagliflozin + saxagliptin
canagliflozin + metformin
ertugliflozin + metformin
ertugliflozin + sitagliptin

These were tagged using the variable:

combination_product

This variable was preserved in all downstream joins and outputs. The rationale is that all SGLT2 inhibitor-containing products should be included in the primary utilisation estimate, while single-agent-only analyses can be used as sensitivity analyses to better approximate heart failure or kidney disease-directed uptake.

Joining strategy

The SDUD data were joined to the SGLT2 inhibitor NDC lookup table using the 11-digit NDC.

The key join was:

SDUD NDC = FDA-derived ndc_11

An inner_join-equivalent SQL join was used rather than a filtering-only join, so that drug metadata from the lookup table was preserved in the extracted SDUD rows.

The joined dataset retained:

sglt2_drug
PROPRIETARYNAME
NONPROPRIETARYNAME
combination_product
active_currently

This allows downstream analyses by parent drug, product type, and single-agent versus combination product status.

⸻

Computational approach

Because the full SDUD files contain millions of rows, the extraction was performed using DuckDB from R rather than loading all records into memory.

The R packages used included:

library(DBI)
library(duckdb)
library(tidyverse)
library(here)
library(glue)

DuckDB was used because it can query large CSV files efficiently without requiring the entire dataset to be held in R memory.

A DuckDB database was created in:

data_processed/sdud_analysis.duckdb

The full SDUD CSV files were read into temporary DuckDB tables one year at a time, cleaned to standardised column names, joined to the SGLT2 inhibitor NDC lookup table, and appended into one all-years SGLT2 extract.

⸻

CSV parsing issue encountered and resolved

An initial attempt to read the SDUD CSV using read_csv_auto() failed because DuckDB did not automatically detect quoted product names containing commas.

Example problematic row:

"ZEMPLAR, 5"

Because the quote character was not detected, DuckDB interpreted the comma inside the product name as a delimiter and reported too many columns.

The issue was resolved by explicitly specifying the quote character when reading the CSV:

read_csv(
  file_path,
  header = true,
  delim = ',',
  quote = '"',
  all_varchar = true,
  ignore_errors = false
)

This successfully loaded the SDUD CSV files with the correct 15 columns.

3. 2020 incompleteness identified

When prescriptions were checked by year and quarter, the 2020 data contained only:

2020 Q4

The 2020 file did not contain Q1, Q2, or Q3. Therefore, 2020 is incomplete in the current raw data.

This was identified from the state-quarter summary:

2019 Q1–Q4 present
2020 Q4 only
2021 Q1–Q4 present

Because 2020 only contains Q4, it should not be treated as a complete calendar year in analyses.

Planned handling:

* Keep 2020 in the raw extracted outputs for transparency.
* Exclude 2020 from the main modelling dataset unless a complete 2020 SDUD file is later obtained.
* Consider sensitivity analyses excluding 2020 and possibly 2021, given COVID-era disruption and evolving SGLT2 inhibitor indications.

A defensible methods statement would be:

“The 2020 SDUD extract available for analysis contained only Q4 data; therefore, 2020 was excluded from primary state-quarter modelling to avoid incomplete calendar-year ascertainment. Sensitivity analyses additionally excluded 2021 to account for COVID-era disruption and transitional uptake around expanded SGLT2 inhibitor indications.”

Jurisdiction checks

The number of reporting jurisdictions increased from 52 to 53 from 2023 onward. Investigation showed that the additional jurisdictions included:

PR
XX

PR

PR is Puerto Rico. It appears as a Medicaid reporting jurisdiction but is not one of the 50 U.S. states or the District of Columbia.

XX

XX appears to be a non-state, unknown, aggregate, or special reporting code. It is not a valid U.S. state or DC code.

For the main state-level analysis, the analytic sample should be restricted to the 50 U.S. states and the District of Columbia:

valid_50dc <- c(state.abb, "DC")
main_50dc <- main %>%
  filter(state %in% valid_50dc)

This gives the desired 51 jurisdictions.

A defensible methods statement would be:

“Analyses were restricted to the 50 U.S. states and the District of Columbia. Puerto Rico and non-state aggregate or unknown reporting records coded as XX were excluded because key state-level covariates were not consistently available or interpretable for these reporting areas.”

Planned primary outcome

The primary outcome will be:

Quarterly state-level SGLT2 inhibitor prescriptions

from the SDUD variable:

Number of Prescriptions

The preferred rate expression will be:

SGLT2 inhibitor prescriptions per 10,000 Medicaid beneficiaries

Formula:

Prescription rate = SGLT2i prescriptions / Medicaid enrolment × 10,000

For regression modelling, the preferred approach is to model prescription counts directly using a negative binomial model, with Medicaid enrolment as an offset:

Outcome: SGLT2i prescription count
Offset: log(Medicaid enrolment)
Model: negative binomial regression
Interpretation: adjusted incidence rate ratio for SGLT2i prescribing rate

Draft methods language

The following paragraph can be adapted for the manuscript methods section:

We used the Medicaid State Drug Utilization Data (SDUD) to quantify quarterly state-level SGLT2 inhibitor utilisation. Annual SDUD CSV files from 2015 to 2025 were downloaded and retained as raw source files. SGLT2 inhibitor records were identified using an independently constructed package-level NDC lookup table derived from the FDA NDC Directory product and package files. Products were identified using generic and proprietary names for canagliflozin, dapagliflozin, empagliflozin, ertugliflozin, bexagliflozin, and sotagliflozin, including fixed-dose combination products. FDA package NDCs were converted to the standard 11-digit 5-4-2 claims format and joined to SDUD records using the SDUD NDC field. Fee-for-service and managed care utilisation records were combined within state-quarter strata. The primary outcome was the number of Medicaid-reimbursed SGLT2 inhibitor prescriptions per state-quarter. Combination products were retained in the primary analysis and excluded in sensitivity analyses. Analyses were restricted to the 50 U.S. states and the District of Columbia; Puerto Rico and non-state aggregate or unknown records coded as XX were excluded. The 2020 SDUD extract available for analysis contained only Q4 data and will be excluded from primary modelling unless complete 2020 data are obtained.
